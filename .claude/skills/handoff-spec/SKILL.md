# Dev Handoff Spec Generator

Дополнение к Figma Inspect для тех, у кого доступа к файлу нет. Ключевая ценность — **имя токена рядом с числом**, потому что голое число превращается в хардкод в коде и уезжает при первом же изменении темы.


## Перед первой командой

Если открыт больше чем один Figma-файл, команда без адреса вернёт 409 со
списком — это не сбой, а вопрос «в каком файле». Выбирать за пользователя
нельзя: правка уйдёт в чужой файл молча. Спросить и закрепить на сессию:

```powershell
$env:FIGMOSHA_SESSION = "<имя файла или sid>"   # разово: --session <имя>
```

Что подключено — `python figmosha.py sessions`.

## Шаг 0 — не выпускать спеку по грязному фрейму

Прогнать `ds-review` (или спросить, прогонялся ли). Если есть неотвязанные значения — спека всё равно делается, но **с блоком «Outstanding issues» первым разделом**. Разработчик, читающий спеку, должен видеть, что часть чисел не токенизирована, а не узнавать это при интеграции.

## Шаг 1 — извлечь

```bash
{ echo 'const ROOT_ID = "185:21880";'
  cat .claude/skills/handoff-spec/scripts/extract.js; } > "$SCRATCHPAD/spec.js"
python figmosha.py exec --file "$SCRATCHPAD/spec.js" --timeout 120
```

Вернётся:
- `layout` — по каждому auto-layout контейнеру: direction, gap, padding, sizing + токен на каждое значение;
- `typography` — размер, вес, line-height, letter-spacing, цвет + text style / переменная;
- `colors` — fill/stroke по слоям с именем переменной;
- `radius`, `sizing` — то же с токенами;
- `instances` — какой компонент, какой вариант, какие пропсы;
- `untokenized` — всё, за чем токена не нашлось.

## Шаг 2 — документ

Писать в `docs/handoff/<frame>-<YYYY-MM-DD>.md`. Структура:

```markdown
# <Frame name> — dev spec
Source: Figma node `185:21880` · generated <date>

## Outstanding issues        ← только если untokenized не пуст
| Element | Property | Raw value | Note |

## Layout
| Container | Direction | Gap | Padding | Sizing | Tokens |

## Typography
| Element | Style | Size/LH | Color | Token |

## Colors
| Element | Property | Value | Token |

## Components used
| Instance | Component | Variant / props |

## Sizing & radius
| Element | Property | Value | Token |
```

**Каждая строка со значением обязана иметь колонку Token.** Токена нет → писать `— (raw)`, не оставлять пусто и не подставлять правдоподобное имя.

## Шаг 3 — редлайн на канвасе (по запросу)

Только если попросили визуальный редлайн:

```bash
python figmosha.py clone <frame-id> --right --gap 200 --name "<Frame> — Redline"
```

Аннотации класть **на копию, рядом с контентом, а не поверх него** — подпись, попавшая внутрь макета, рано или поздно уедет в продакшн как элемент интерфейса. Вернуть id копии.

## Guardrails

- **Значение без имени токена не выпускается молча.** Либо токен, либо явная пометка `raw`.
- **Не выдумывать имена токенов.** Только те, что реально привязаны (скрипт резолвит id → имя). Не привязано → `raw`.
- **Не выдавать resolved-число вместо токена.** `16px` и `spacing/md` — разные вещи для того, кто пишет код.
- Не аннотировать оригинальный фрейм — только копию.
- Не заходить внутрь инстансов: для них указывается компонент + вариант, а размеры берутся из библиотеки.
- Не проверять итог скриншотом — данных достаточно.
