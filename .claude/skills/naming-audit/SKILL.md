# Layer & Naming Hygiene Audit

Двухфазный: сначала карта переименований, потом — по подтверждению — применение.


## Перед первой командой

Если открыт больше чем один Figma-файл, команда без адреса вернёт 409 со
списком — это не сбой, а вопрос «в каком файле». Выбирать за пользователя
нельзя: правка уйдёт в чужой файл молча. Спросить и закрепить на сессию:

```powershell
$env:FIGMOSHA_SESSION = "<имя файла или sid>"   # разово: --session <имя>
```

Что подключено — `python figmosha.py sessions`.

## Шаг 1 — вывести конвенцию из файла

Не навязывать свою. Взять 3–4 хорошо организованных фрейма/компонента как эталон:

```bash
python figmosha.py tree <ref-id> --depth 3 --no-size --no-text
```

Сформулировать паттерн в одну строку (например `Section/Element-role`, или `Component/Variant=X`) и **показать пользователю**: «конвенция файла, как я её прочитал: …». Дальше всё меряется этой строкой.

## Шаг 2 — скан

```bash
python figmosha.py exec --file .claude/skills/naming-audit/scripts/scan-names.js \
  --set ROOT_ID=185:21880 --timeout 120
```

Вернётся:
- `defaults` — слои с дефолтными именами (`Frame 12`, `Rectangle 47`, `Group 3`, `Ellipse 8`, `Vector`, `Line 1`);
- `duplicates` — одинаковые имена среди сиблингов (ломают `h.findByName`, который берёт первый попавшийся);
- `risky` — слои, на которые есть ссылки: имена вариантов, слои внутри компонентов, цели instance-swap;
- `unnamedText` — TEXT-ноды, чьё имя = их содержимому (дефолт Figma), из-за чего имя плывёт при каждой правке текста;
- `stats` — глубина, ширина, доля именованных.

## Шаг 3 — rename-map

Формат фиксированный:

```
Current name     | id         | Suggested name        | Risk
Frame 12         | 185:22001  | Card/Content          | —
Rectangle 47     | 185:22004  | Card/Bg               | —
Group 3          | 185:22011  | Card/Actions          | внутри компонента
```

Разложить по фактическому дереву — имя должно объяснять роль слоя в родителе, а не просто перестать быть дефолтным. `Frame 12` → `Frame` это не результат.

## Шаг 4 — организация страницы

Отдельно, коротко: сгруппированы ли родственные фреймы так же, как остальной файл; есть ли осиротевшие ноды на верхнем уровне; совпадает ли порядок с логикой остальных страниц. Это наблюдения, не переименования.

## Шаг 5 — применение (только после «да»)

```bash
python figmosha.py exec --file .claude/skills/naming-audit/scripts/apply-renames.js \
  --set 'RENAMES=[{"id":"185:22001","to":"Card/Content"}]'
```

Скрипт возвращает `{id, before, after}` по каждому — приложить к ответу как подтверждение, что применилось именно задуманное.

## Guardrails

- **Не переименовывать на первом проходе.** Сначала карта, потом подтверждение. Даже `Rectangle 47`.
- **Не трогать слои из `risky`, не проговорив зависимость.** Переименование слоя внутри компонента ломает override'ы в существующих инстансах, а переименование варианта — `setProperties` в коде и в других файлах. Это необратимо по факту (Figma не пересвязывает).
- **Не изобретать конвенцию.** Она выводится на шаге 1 из файла. Если файл не консистентен — сказать это прямо и предложить выбрать эталон, а не выбирать за пользователя.
- Не переименовывать слои внутри инстансов — правится мастер-компонент.
- Не «улучшать» заодно структуру (перемещать, группировать) — это другой запрос.
