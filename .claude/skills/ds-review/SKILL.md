# Design System Review

Аудит-проход по фрейму. **Ничего не чинит** — только отчёт. Фиксы отдельным шагом после подтверждения.


## Перед первой командой

Если открыт больше чем один Figma-файл, команда без адреса вернёт 409 со
списком — это не сбой, а вопрос «в каком файле». Выбирать за пользователя
нельзя: правка уйдёт в чужой файл молча. Спросить и закрепить на сессию:

```powershell
$env:FIGMOSHA_SESSION = "<имя файла или sid>"   # разово: --session <имя>
```

Что подключено — `python figmosha.py sessions`.

## Шаг 0 — связь

```bash
python figmosha.py doctor
```

Порт у каждого проекта свой (`project.json`), поэтому адрес не пишем руками.
Мост или плагин не отвечает — `doctor` называет починку. Не начинать аудит вслепую.

## Шаг 1 — определить корень

Если id не назван — брать текущее выделение:

```bash
python figmosha.py sel
```

Пусто → спросить пользователя, что аудитить. Не аудитить всю страницу «на всякий случай».

Разобрать один подозрительный узел (что привязано, что хардкод) — `python figmosha.py props <id>`:
значение со стрелкой `→ токен` привязано, без стрелки — сырое.
Поехавший лейаут — `props <id> --children`: там видно `FILL`/`HUG`/`FIXED` каждого ребёнка.

## Шаг 2 — вывести шкалу спейсинга из самого файла

Не брать значения из головы. Собрать фактические:

```bash
python figmosha.py exec --file .claude/skills/ds-review/scripts/spacing-scale.js
```

Скрипт вернёт гистограмму `itemSpacing`/padding по странице. Частотные значения = фактическая шкала. Если в файле есть коллекция переменных spacing — она главнее, гистограмма только дополняет.

## Шаг 3 — скан

Скрипту нужен `ROOT_ID`. Значения передаются флагом, файл не трогается:

```bash
python figmosha.py exec --file .claude/skills/ds-review/scripts/scan.js \
  --set ROOT_ID=185:21880 \
  --set 'SCALE=[0,4,8,12,16,24,32,40,48,64]' \
  --timeout 120
```

Вернётся JSON: `rawFills`, `rawStrokes`, `rawText`, `offScale`, `rawRadius`, `instances`, `totals`.

## Шаг 4 — контраст (только если в скане есть текст)

```bash
python figmosha.py exec --file .claude/skills/ds-review/scripts/contrast.js \
  --set ROOT_ID=185:21880 --timeout 120
```

Считает WCAG-контраст текста против ближайшего непрозрачного фона-предка. Порог: 4.5 для обычного текста, 3.0 для ≥18pt или ≥14pt bold — скрипт применяет это сам.

## Шаг 5 — severity

| Severity | Что сюда попадает |
|---|---|
| **blocker** | контраст ниже порога; текст цветом-хардкодом на цветном фоне; отвязанный фон, который сломается в тёмной теме |
| **high** | fill/stroke сырым hex там, где для этого цвета есть переменная; отсоединённый компонент (detached) |
| **medium** | спейсинг вне шкалы; радиус вне шкалы; текст без text style |
| **low** | одиночное отклонение внутри декоративного слоя; спейсинг, отличающийся от шага шкалы на ≤2px |

## Шаг 6 — отчёт

Формат фиксированный, менять нельзя:

```
Area          | Verdict | Count | Note
Color tokens  | fail    | 7     | 7 сырых fill; см. таблицу ниже
Spacing       | pass    | 0     | всё по шкале 4/8/16/24
...
```

Затем таблица находок, отсортированная по severity:

```
Severity | Node                  | id         | Issue                    | Suggested fix
blocker  | Card/Title            | 185:21901  | контраст 2.9 на #1E1E1E  | text/primary-inverse
```

Отчёт сохранять в `docs/audits/<frame>-<YYYY-MM-DD>.md`, чтобы прогоны сравнивались между собой. Если каталога нет — создать.

## Guardrails

- **Аудит первым проходом. Ничего не чинить без подтверждения.** Даже «очевидный» хардкод.
- **Не выдумывать имена токенов.** Предлагать только те, что реально есть в файле — проверить через `figma.variables.getLocalVariablesAsync()`. Нет подходящей переменной → писать «токен отсутствует, нужен новый», а не изобретать имя.
- **Не выдумывать числа контраста.** Только то, что вернул скрипт. Не посчиталось (градиент, картинка, прозрачность) → `needs manual check`.
- **Не заходить внутрь инстансов.** Скрипт этого не делает намеренно: содержимое инстанса — ответственность мастер-компонента, флагать там нечего.
- Если в файле есть заметка о принятом техдолге — не флагать задокументированное повторно.
- Не проверять результат скриншотом. Данных из скрипта достаточно.
